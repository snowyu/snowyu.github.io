1.2 它们共同验证了什么（以及代价）

核心命题：推理质量更依赖计算深度，而不是参数宽度。

但 2026 年的证据已经把这句话变成了一笔可定价的交易：

Inkling 2 Mini 的对照实验里，不循环的模型训练时只少花 7.5% 计算，但若要在 512K-token agentic trace 上追平循环版本的 loss，
推理时需要多花 140% 的计算。 [T2]

同一篇博客还给出了循环位置的定价：把中间 12 层循环，等效算力增益
1.51–1.91×；把最后 12 层循环只有 1.24–1.36×（28 项评测里 27 项中间更好）[T2]。

换句话说，"深度换参数"是真的，但深度不是免费的——这正是本报告第 9 节要问的问题。

既不支持也不反驳。详见 §2.5。

2. 基础

2.1 标准 Transformer 的瓶颈

标准 Transformer 中，模型深度 = 参数数量：

这个 1:1 的耦合关系是传统扩展的主要约束。

2.2 Looped Transformer 的核心思想

打破深度与参数的 1:1 耦合——让部分层重复执行：

类比：像一个人反复读同一段文字。第一遍取大意，第二遍看细节，第三遍发现隐含逻辑——每次都用同一个大脑，理解逐层加深。

代价同样来自这个类比：每多读一遍，就多用一份时间（推理延迟），而大脑的体积（内存）不变。

2.3 三个关键概念

（a）Prelude / Core / Coda 三段式

两个模型都把解码器分三段：

  • Prelude（前导）：跑一次，负责嵌入与内部表征之间的"翻译"
  • Core（循环核心）：跑多次，承载抽象推理
  • Coda（尾随）：跑一次，负责输出侧的"翻译"

这个三明治结构在 2026 年已被对照实验支持：三轴解耦研究发现 prelude–core–coda
结构在上下文抽取与推理任务上一致更好 [A11]；TML 也给出同样的直觉说明 [T2]。

（b）“推理等效参数”（inference-equivalent parameters）

SenseNova 说"约 14.6B 推理等效参数"时，指的是：

每个 token 实际执行的计算量，等效于一个 14.6B 参数的非循环稠密模型 [S1]。

不是说模型存了 14.6B 参数——它只存了 9,656,254,576 个 [S6]。（TML 的对比表把 SenseNova 记作 9.4B / 14.6B，商汤自己写"约 9B"，实测 safetensors 统计为 9.66B——差异来自是否计入 ViT、MTP draft、FP32 mHC
路由参数。引用时必须注明口径。[T1][S1][S6]）

（c）“有效活跃参数”（effective active parameters）

对 MoE 模型（Inkling 2 Mini）：

一个 token 在前向传播中实际触碰到的权重总量（含循环重复触碰的）[T1]。

3.4B 是一次完整传播中激活的唯一权重；5.4B 是三遍循环后的总触碰量 [T1]。

共同的陷阱：这两个指标都是"权重触碰量"的代理，不等于 FLOPs。注意力 FLOPs 随上下文长度增长，而权重触碰量不变；MoE 的"读取带宽"和"计算量"
也不是一回事。§8 会分开处理。

这一侧，且都是 MoE。

2.5 Ouro 该不该算家族成员？——该，但按"第一代"引用

结论：应纳入，但它的证据身份是"可行性证明 + 工具箱"，不是"效果证明"。以下数字全部来自 Ouro 官方项目页 [P1] 与论文 [A2]。

它证明了什么（值得吸收）

  1. 循环要在预训练期就学会，而不是事后加。7.7T tokens 的完整配方：
    warmup → Stable-I 3T(4K) → 分叉（2.6B 由 upcycle 复制层得到）→
    Stable-II 3T（带 4 遍，为稳定性）→ CT anneal 1.4T(16K) →
    LongCT 20B(64K) → mid-training 300B(32K) → Reasoning SFT ~8.3M 例 [P1]。循环没有破坏预训练标度——这是后面所有工作的前提。
  2. 深度是可控量：每个 loop 挂 LM head + exit gate，
    loss = exit 概率加权的任务 loss − β·H(exit 分布)；第二阶段只训 gate；推理时按累积 exit 概率阈值 q 退出（Q-exit）[P1]。商汤宣称的 Dynamic Loop 属于同一条路线 [S1]。实测 trained gate 在每个预算下都最好（2.5 遍时 MMLU ≈ 66%，4 遍 67.35%）[P1]。
  3. 收益来自"知识操作"而非"知识存储"，且 latent reasoning 比显式 CoT 更忠实 [P1]
    ——与 §5、§6.3 的结论一致。
  4. Apache-2.0 权重可复现；158 篇引用 / 35 篇实质性跟进（15 篇直接跑 Ouro ckpt） [P1]。

它的证据边界（不能作为效果证据引用）

  1. 规模不可比：只有 1.4B / 2.6B。R=4 后每 token 触碰量约 9–10B
    (推断：层参数 ×4 + 嵌入)，仍低于 SenseNova 的 14.6B；它从未在 ≥9B 体量上测试全栈循环。

  2. 对照不是等算力：比的是 Qwen3-1.7B / 4B / 8B、Gemma3-4B / 12B。拆 MMLU：Ouro-2.6B 74.6 只赢 Qwen3-4B 73.2，输给 Qwen3-8B 76.6；
    GSM8K 81.58 < Qwen3-8B 83.09。“最高匹敌 12B"里的 12B 是较弱的 Gemma3-12B [P1]。
    → 不能读成"2.6B 循环模型 ≈ 12B”。

  3. 没有 span 消融：R 固定 4、全栈固定，从未扫跨度 → 对 H1/H2 不构成证据。

  4. 超过训练深度会退化（6-benchmark 平均）[P1]：

    循环步数 T 1 2 3 4 5 6 7 8
    Ouro-1.4B 49.93 66.90 71.55 72.39 71.32 71.14 70.49 69.87
    Ouro-2.6B 59.98 73.37 76.58 77.44 77.23 76.94 76.84 76.44

    峰值正好在训练深度 T=4，之后单调下降。这比 SenseNova 的
    "2→4 遍只 +1.04/+1.35 pp"更尖锐：全栈 4 遍已经是这种模型的甜点 [P1][S1]。

  5. 第一代最大的负债是 4 份 KV：官方自测只保留最后一遍 cache（¼ 内存），
    GSM8K 78.92→78.85 几乎无损，但 MATH-500 82.40→80.40（−2.0 pp）；只保留第一遍则崩溃（18.73 / 8.43）[P1]。第二代的 MELT / LLA / HLA /

4. Loop 内部机制深度剖析

这是两个模型最核心的分歧点。

4.1 SenseNova：串联循环 + 双流 mHC

循环间：简单串联

循环内：双流 mHC 保护信息流

mHC（流形约束超连接）的配置范围是 start: 4, end: 28——
恰好只覆盖循环块，且不能跨越循环阶段边界 [S6][S7]：

Sinkhorn 归一化：交替做行归一化与列归一化 20 次，使混合矩阵接近双随机（行和与列和均为 1），防止信息在混合过程中单向流失 [S1]。

与论文的关系：Hyperloop Transformers 用"每个 loop 之后施加超连接"来稳定循环，并称这带来约 50% 的参数节省 [A5]。SenseNova 是同一思路（manifold-constrained
hyper-connections，缩写 mHC）的产品化版本，但没有公开训练细节。

混合注意力

线性注意力侧的规格（[S6]）：16 个 key head × 128 维、32 个 value head × 128 维、短卷积核 4。 (推断) 递推状态约 32 × 128 × 128 ≈ 0.52M 元素/层，
BF16 下 24 层合计约 25 MiB/序列，与上下文长度无关——所以"线性注意力状态可忽略"
在长上下文下成立，但它不是 0，且会主导极短上下文的显存构成。

主干与工程实现

SenseNovaLoopConfig 继承 Qwen3_5Config，注意力用 SDPA [S6][S7]——
也就是说 SenseNova 是在成熟的 Qwen3.5 类主干外面套了一层循环 + mHC。这一点比"原生支持"更准确地解释了它的生态成熟度（详见 §10.3）。

滑动窗口层的特殊处理

Inkling 的注意力是混合的：20 个滑窗层（窗口 1024）+ 4 个全注意力层
（层 5、11、17、23；layer_types 由 (i+1) % 6 == 0 生成）[T7][T9]。

一个重要细节：滑窗层在第一遍把 Q/K/V 从同一个输入投影；第二遍及以后，由于 Q/K/V 各自收到不同 message，它们变成三个独立输入 [T9]。

注意力的其他细节

  • 24 个 query head、8 个 KV head，head_dim = swa_head_dim = 128 [T7]
  • 学习式相对位置 bias + sink + 输出门；全注意力层还带 dynamic K/V 卷积 [T8][T9]
  • 短卷积 conv_kernel_size = 4，需要 per-pass 的 conv-state [T7][T6]
  • Transformers 实现里注意力只能 eager 模式（因为有相对 bias 与 sink）[T6]
  • 每个 pass 有自己的 KV cache 与 conv-state cache：48 + 48（不是 24 + 24）[T6][T9]

官方 checkpoint 内含 3 层 DSpark draft（mtp_config，intermediate 9216），读取目标模型在 layer-visit 5 / 23 / 41 以及最终归一化状态 [T7][T9]；

6. 优劣之争：机制假说与 Benchmark 证据

6.1 为什么直觉上"草稿纸式"更优越？

以下是机制推理，不是实验结论（目前没有公开对照实验分离这两种拓扑）：

（a）无信息瓶颈

（b）门控自适应

rank-64 控制器的 forget / gain 两路让模型能逐通道决定遗忘（→0）或注入（→1）[T9]。

（c）错误恢复能力

串联式里第一遍的错误直接进入第二遍输入；门控式可以过滤掉一部分。

支持这两个直觉的间接证据：Inkling 论文式实验显示 message 融合让循环在512K agentic trace 上有效（non-loop 需多 140% 推理计算才能追平）[T2]；而循环模型研究中确实发现"多遍之间表征平面的收敛程度"决定了 KV 平面能否共享（所谓 ripeness）[A15]——这与"第二遍面对的是分布不同的输入"是同一现象的另一面。

6.2 但深井式并非一无是处

（a）实现简洁性

（b）Kernel 开销才是 batch=1 的真实瓶颈

对循环模型的系统测量显示：Ouro 在 batch 1 时"融合所有 loop 提交"几乎不涨（0.99×），每 token 5,689 个小 kernel 才是成本；在保持结果逐位一致的前提下做融合可把吞吐提到 1.11–1.59× [A18]。这说明"串联更简单"的收益主要在
kernel 层面，而不是 FLOPs 层面。

（c）生态成熟度

SenseNova 有 10 家以上国产芯片 Day-0（壁仞、光本位、寒武纪、海光、昆仑芯、摩尔线程、沐曦、昇腾、曦望、曦智）[S4]。但要注意措辞：
